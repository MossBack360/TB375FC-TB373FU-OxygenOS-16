# Speaker rotation ROM stage and hall audit (2026-11-15)

The owner confirmed that the event-driven v2.4 Magisk test changes the speaker channels correctly. `patch/stage_speaker_rotation_rom.py` copied the exact tested JAR (SHA-256 `97a873132db89c6ec6a3f784c2e3760a807b6bed23671be443b72ad962773004`) into the v5 unpacked `system_a` tree and added `/system/etc/init/fixo-speaker-rotation.rc`. That init definition starts after `sys.boot_completed=1`, runs as root in `u:r:shell:s0`, and leaves process supervision to init. Both files have explicit `system_a_fs_config` and file-context entries. A read-only/manual dry run with `su -Z u:r:shell:s0 0` confirmed the helper could subscribe to the rotation callback and call `AudioSetParam` in that domain. Final native init startup still requires a ROM boot to verify. No image has been rebuilt or flashed.

The hall-cover fix is **not yet solidified**. Historical module `11-hall-cover-settings-bridge-v2.0.zip` has ID `xiaoxin_hall_cover`; it listens to the `hall` input device and reads `/sys/bus/platform/drivers/hall/hall_status`, then issues sleep/wake only while `Settings.Global.device_case_enabled=1`. It is not in the current device module list. The hardware interface exists (`hall_status=1`, `/dev/input/event4` named `hall`, switch value `1`). But `u:r:shell:s0` cannot read either the hall sysfs node or event4; both return Permission denied. Copying its script into a root/shell init service would therefore fail. It needs a narrowly scoped SELinux domain/policy grant or another privileged event source before a ROM-owned service can replace the Magisk daemon. This audit did not change the hall behavior or install the historical module.
