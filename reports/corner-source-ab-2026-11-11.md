# Corner source A/B trial

The owner asked whether the visible window corners come from `ro.oplus.display.rc.size` or Android `Display.getRoundedCorner()`. Before the trial, the OPlus property was `26,26,26,26` and all four framework display corners were radius 0. The old SystemUI v0.5 and bottom-corner feature module v1.3 were enabled; the `fixo_display_corners_rro` and PiP RenderEngine no-clip modules were disabled.

Stage A changes only the first two comma-separated OPlus property entries to the ROM's original 65, leaving the last two at 26: `65,65,26,26`. The archive is `out/transition-corner-asym-v1.2-test-2026-11-11/fixo-transition-corner-asym-v1.2-test.zip`, SHA-256 `c9093b6074d8882773355947ef05a3ef1ae9a3a76a778c6c08b703281527e3f7`. It upgrades the same `fixo_launcher_corner_radius` module ID. After reboot, the property readback matched, while the framework `rounded_corner_radius` stayed `0.0dip`. The owner is testing the visual result. The inspected Launcher `RoundCornerLoader` reduces the four entries to their minimum, so its own effective value should remain 26; other per-entry consumers are unconfirmed.

Stage B is built but not yet installed: `out/display-corner-rro-v0.3-asym-2026-11-11/fixo-display-corner-rro-v0.3-asym-test.zip`, SHA-256 `3db37781f75c32aebb10391c0f4c1987109a998cd5c318197efce07a82fef7d5`. It keeps default radius 26px and sets the top pair to 48px, bottom pair to 16px. The v0.3 source is `patch/display-corner-rro-v0.3-asym/`; the compiled APK resource table was checked. Install only after the owner reports Stage A, so the two inputs can be distinguished.

The owner saw no change at `65,65,26,26` and requested all-zero OPlus values. Stage A2 is `out/transition-corner-zero-v1.3-test-2026-11-11/fixo-transition-corner-zero-v1.3-test.zip`, SHA-256 `24d56ed88f47d00c45ca3061b1326b3f43754ab2dad16302d60a2201932504ab`. It upgrades the same property module ID. After reboot, `ro.oplus.display.rc.size=0,0,0,0`, `rounded_corner_radius=0.0dip`, and SystemUI v0.5 remains mounted. Visual result is pending.

The owner then reported that app-opening and background-switch animations visibly became square at `0,0,0,0`. This confirms that this OPlus property affects those transitions. The owner questioned whether the Android display-corner source had been measured correctly and requested a value change.

Stage B was then installed, keeping the OPlus property all zero. After reboot, `sys.boot_completed=1`, the three framework resource lookups reported default 26px, top 48px, bottom 16px. `dumpsys window displays` reported current landscape corners TopLeft 48, TopRight 16, BottomRight 16, BottomLeft 48: the natural-orientation top/bottom resources map to left/right in this orientation. SystemUI v0.5 was still mounted, SHA-256 `92c57e647c9520cb043be1d0a0cf010c6f1e7dec2b72129837b45cc261e57560`. Visual effect of Stage B is pending owner feedback.

The owner could not see a meaningful change from the 48/16 test and requested a conspicuous value. Stage C upgrades the same overlay module to `out/display-corner-rro-v0.4-100px-2026-11-11/fixo-display-corner-rro-v0.4-100px-test.zip`, SHA-256 `17ec2a514f2ca100250404cd546cab92853bf5d34cf64a9740577e6e6c70af92`. Decompiled `RoundedCorners.fromRadii()` clamps negative radii to zero and scales for physical display ratio but has no explicit upper cap in the inspected path; 100px is well below half either screen dimension. After reboot, framework lookup reports 100px and all four `mRoundedCorners` report radius 100. The OPlus property remains `0,0,0,0` and SystemUI v0.5 remains mounted. Visual result is pending.

At OPlus all-zero and framework 100px, the owner observed a clear change only in app-opening animation. The owner next requested both sources at 100. After a transient restoration to 26/26 that was interrupted and reversed, Stage D upgraded the property module using `out/transition-corner-100-v1.4-test-2026-11-11/fixo-transition-corner-100-v1.4-test.zip`, SHA-256 `9d8f00d48010f066d0bf8e75d81d8dd156dc9e5b05376f21ee99a703e401f707`. Current readback after reboot is `ro.oplus.display.rc.size=100,100,100,100`, framework lookup 100px, and all four `mRoundedCorners` radius 100. Visual result of the 100/100 combination is pending.

The owner rejected the 100/100 appearance and requested both values restored to 26. The archived property module v1.1 and framework RRO v0.2 were reinstalled. After reboot, `sys.boot_completed=1`, `ro.oplus.display.rc.size=26,26,26,26`, `rounded_corner_radius=26.0px`, and all four `mRoundedCorners` report radius 26. Preserve the all-zero, 65/26, 48/16, and 100px archives as experiments only; do not place them in a stable installer set.
